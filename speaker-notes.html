Opening

Set the map before commands.

Open presentation section

Purpose

Frame Git as a model: objects, states, workflow, branching choices, quality gates, conflicts, and undo decisions.

Presenter cues

  • Ask who has used git add, seen a conflict, or can explain HEAD.
  • Tell the room that terminal commands are evidence; the presentation stays the guide.
  • Keep the pace conceptual before opening the demo repository.

Transition: Before commands, let's look at what Git stores.

Demo 1

Commits point to snapshots.

Open presentation section

Purpose

Show that commits point to trees, trees point to blobs, and refs point to commits.

Setup
cd /Users/kadphol/Documents/git-sharing/taskly
git switch main
git status --short
Presenter commands
git log --oneline -5
git cat-file -p HEAD
git cat-file -p HEAD^{tree}
git cat-file -p HEAD:src/tasks.js
find .git/objects -maxdepth 1 -type d | sort | head
cat .git/refs/heads/main
cat .git/HEAD

Watch for

  • HEAD is a commit object with metadata, parent, and tree pointer.
  • HEAD^{tree} maps names to tree and blob IDs.
  • Branch refs are plain pointers to commit SHAs.

Transition: Now let's see how a change becomes a snapshot.

Demo 3

Branch, change, stage, commit, push.

Open presentation section

Purpose

Walk through feature-branch work without requiring a real remote repository.

Setup
cd /Users/kadphol/Documents/git-sharing/taskly
git switch main
git reset --hard workshop-main
git branch -D demo/basic-workflow 2>/dev/null || true
Presenter commands
Create and commit branch work

git branch --show-current

cat > src/labels.js <<'EOF'
function taskLabel(task) {
  return task.done ? '[done]' : '[todo]';
}

EOF

git status

Remote teaching point

  • The first block creates local feature branch history.

  • The push fails unless a remote exists; use that to explain publishing.

git reset --hard workshop-main

Transition: Branching is not only a command; it is a release agreement.

Discussion

Choose the collaboration model.

Open presentation section

Purpose

Use vocabulary and tradeoffs. Do not turn this part into a command demo.

Prompt the room

  • Which strategy do we use today?
  • How long do branches normally live?
  • Where does release control happen?
  • What bottleneck hurts most: review, CI, QA/UAT, or approval?

Recommendation

Default to GitHub/GitLab Flow. Move toward trunk-based development when CI and feature flags are strong. Add release branches when release governance needs them.

Presentation jumps

  • Trunk-Based Development
  • Git Flow
  • GitHub Flow
  • GitLab Flow
  • Release Branches

Transition: Whatever branching model we choose, quality checks should happen before bad code reaches main.

Demo 4

Fast local quality gates.

Open presentation section

Purpose

Explain where hooks fit and why local hooks should be fast and clear.

Setup
cd /Users/kadphol/Documents/git-sharing/taskly
git switch main
git reset --hard workshop-main
git branch -D demo/hooks-example 2>/dev/null || true
git switch -c demo/hooks-example
Presenter commands
Create hook
mkdir -p .git/hooks

cat > .git/hooks/pre-commit <<'EOF'
#!/usr/bin/env sh
echo "pre-commit: checking for TODO markers"
if grep -R "TODO" src >/dev/null 2>&1; then
  echo "pre-commit: TODO marker found"
  exit 1
fi
EOF
chmod +x .git/hooks/pre-commit
Trigger hook
printf '\n// TODO: validate input\n' >> src/tasks.js
git add src/tasks.js
git commit -m "demo: trigger hook"

git status --short
git restore --staged src/tasks.js
git restore src/tasks.js
git status --short

Watch for

  • The commit is blocked by a non-zero hook exit.
  • Hooks live in .git/hooks for this local repo.
  • Real teams often use Husky, Lefthook, pre-commit, lint-staged, or CI.
Reset
rm -f .git/hooks/pre-commit
git restore --staged src/tasks.js 2>/dev/null || true
git restore src/tasks.js
git switch main
git branch -D demo/hooks-example

Transition: Hooks catch predictable issues. Conflicts need a human decision.

Demo 5

Conflict markers are a decision request.

Open presentation section

Purpose

Trigger a real conflict, inspect markers, abort once, then resolve the conflict.

Setup
cd /Users/kadphol/Documents/git-sharing/taskly
git switch main
git reset --hard workshop-main
git branch -D demo/conflict-abort-main demo/conflict-main 2>/dev/null || true
Presenter commands
Inspect both sides
git show workshop-main:src/greet.js
git show workshop-feature-greeting:src/greet.js
Abort path
git switch -c demo/conflict-abort-main workshop-main
git merge feature/greeting
git status
cat src/greet.js
git merge --abort
git status --short
Resolve path
git switch -c demo/conflict-main workshop-main
git merge feature/greeting
git status
cat src/greet.js

cat > src/greet.js <<'EOF'
function greet(name) {
  console.log('Good morning, ' + name + '! Welcome back.');
}
module.exports = { greet };
EOF

git add src/greet.js
git commit --no-edit
git log --oneline --graph --decorate -6
node src/app.js

Watch for

  • <<<<<<< HEAD is the current branch.
  • ======= separates versions.
  • >>>>>>> feature/greeting is the incoming branch.
  • Resolution is final file content plus git add.
Reset
git merge --abort 2>/dev/null || true
git switch main
git branch -D demo/conflict-abort-main demo/conflict-main 2>/dev/null || true
git reset --hard workshop-main

Transition: Conflict resolution is one repair. Now choose the right undo command.

Demo 6

Undo depends on sharing risk.

Open presentation section

Purpose

Connect undo commands to whether the work is local or already shared.

Setup
cd /Users/kadphol/Documents/git-sharing/taskly
git switch main
git reset --hard workshop-main
git branch -D demo/undo-local important-work demo/recovered-work 2>/dev/null || true
git switch -c demo/undo-local
Presenter commands
Amend
echo "forgotten note" > note.txt
git add note.txt
git commit -m "docs: add note"

echo "extra line" >> note.txt
git add note.txt
git commit --amend --no-edit
git log --oneline -3
Restore and reset
echo "temporary work" > scratch.txt
git add scratch.txt
git status --short

git restore --staged scratch.txt
git status --short

git add scratch.txt
git commit -m "demo: commit scratch"
git reset --soft HEAD~1
git status --short

git restore --staged scratch.txt
rm scratch.txt
Revert
echo "shared bad change" > revert-target.txt
git add revert-target.txt
git commit -m "demo: shared bad change"

git revert --no-edit HEAD
git log --oneline -5
Reflog recovery
git switch main
git switch -c important-work
echo "important work" > important.txt
git add important.txt
git commit -m "feat: important local work"

git switch main
git branch -D important-work
git reflog -8
git switch -c demo/recovered-work HEAD@{1}
ls important.txt

Watch for

  • commit --amend rewrites the last local commit.
  • restore --staged moves a staged change back.
  • reset --soft removes a commit but keeps staged changes.
  • revert creates a new commit instead of deleting shared history.
  • reflog recovers commits no branch points to anymore.
Reset
git switch main
git branch -D demo/undo-local important-work demo/recovered-work 2>/dev/null || true
git reset --hard workshop-main

Transition: The goal is not memorizing every command. It is knowing where Git keeps the manual.

Emergency reset

Recover a messy demo repo.

Use when

A demo branch, merge, rebase, or local file state gets too messy to explain quickly.

Reset demo repo
cd /Users/kadphol/Documents/git-sharing/taskly

git merge --abort 2>/dev/null || true
git rebase --abort 2>/dev/null || true
git switch main
git reset --hard workshop-main

for branch in \
  demo/basic-workflow \
  demo/conflict-main \
  demo/conflict-abort-main \
  demo/hooks-example \
  demo/recovered-work \
  demo/three-states \
  demo/undo-local \
  important-work
do
  git branch -D "$branch" 2>/dev/null || true
done

git branch -f feature/dark-mode workshop-feature-dark-mode
git branch -f feature/greeting workshop-feature-greeting
git branch -f feature/login workshop-feature-login

git status --short
git log --oneline --graph --decorate --all
